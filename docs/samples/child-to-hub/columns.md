# 列(項目)の意味

## 1. CSV(子ラズパイの中だけにある・送信用)

ヘッダー行なし。1行 = 「その設備の状態コードが変わった」という1件。

`日時, STA_NO1, STA_NO2, STA_NO3, T1_STATUS`

| 列 | 例 | 意味 |
|---|---|---|
| 1 日時 | `20261104130307` | 状態が変わった時刻。`YYYYMMDDhhmmss`(日本時間・14桁の数字) |
| 2 STA_NO1 | `HIME` | 設備を表す3項目の1つ目。子の `id_names_config.json` で設定 |
| 3 STA_NO2 | `ABC` | 同2つ目 |
| 4 STA_NO3 | `001` | 同3つ目 |
| 5 T1_STATUS | `1` | 状態コード(整数)。信号灯の色(on/blink/off)の組み合わせから、子の `status_code_config.json` のルールで決まる |

- 状態コードが**変わったときだけ**1行追加される(毎秒は書かない)。
- 日付が変わった直後は、対象の全設備ぶんの現在の状態を1行ずつ書く。

## 2. JSON(親に実際に届く・MQTT で 1メッセージ = 1件)

CSV の1行が、次の1件の JSON になる。

| 項目 | 型 | 例 | 意味 |
|---|---|---|---|
| `event_id` | 文字列 | `01d21f66…c894` | この1件を一意に決める ID(下記) |
| `mk_date` | 文字列 | `20261104130307` | CSV の日時。そのまま |
| `sta_no1` | 文字列 | `HIME` | CSV の STA_NO1。そのまま |
| `sta_no2` | 文字列 | `ABC` | CSV の STA_NO2。そのまま |
| `sta_no3` | 文字列 | `001` | CSV の STA_NO3。そのまま |
| `t1_status` | **整数** | `1` | CSV の T1_STATUS。文字列から整数に直す |
| `device_id` | 文字列 | `pizero2w` | 送ってきた子ラズパイ。環境変数 `DEVICE_ID`、無ければホスト名 |
| `schema_version` | 整数 | `1` | JSON の形式の版。今は常に `1` |

## 3. `event_id` について

**役割**: 同じ内容を2回送ってしまっても、親が「同じ1件」と判別して二重に登録しないための ID。
通信が切れて再送したときなどに効く。

**作り方**: 次の文字列を SHA-1 でハッシュ化した16進40桁。

```
<device_id>|<日時>,<STA_NO1>,<STA_NO2>,<STA_NO3>,<T1_STATUS>
```

例(サンプルの1行目):

```
pizero2w|20261104130307,HIME,ABC,001,1
   ↓ SHA-1
01d21f6694dc7fb17408149f795190ab9fc9c894
```

**性質**:
- 同じ子・同じ行なら、何度作っても**同じ値**になる(乱数や現在時刻は使わない)。
- 子(`device_id`)・日時・設備名・状態コードのどれか1つでも違えば、**別の値**になる。
- 値から元の内容を読み取ることはできない(ハッシュのため)。

## 4. 親に着いたあと

親は JSON を保存し、Oracle の `HF1RCM01` に次の5列を書く。

| Oracle の列 | JSON の項目 |
|---|---|
| `MK_DATE` | `mk_date` |
| `STA_NO1` | `sta_no1` |
| `STA_NO2` | `sta_no2` |
| `STA_NO3` | `sta_no3` |
| `T1_STATUS` | `t1_status` |

`event_id`・`device_id`・`schema_version` は Oracle には入らず、親の中で重複の判定や送信元の管理に使われる。
