増設

クローンSDは名前がぶつかるのでここで改名する。局番号は空になり、あとで子の画面から付ける。

なぜ改名が要るか

ホスト名はそのまま通信相手の識別子になります。同じ名前が2つあると2台が互いの接続を切り合い、どちらのデータも届かなくなります。クローンSDをそのまま起動してはいけない理由がこれです。

2（増設）を選んだあと

  1. 子をハブの電波につなぐ — クローンSDなら先に「子SDをこのハブ用にする」で鍵とWi-Fiを書いておくと、挿して電源を入れるだけでつながります。
  2. 未登録の端末をさがす — 自動です。「まだ見えません」と出たら子の電源と電波を確かめて選び直します。
  3. 新しい名前を決める — Enter で既定値。既定は <ハブ名>-001 のような3桁連番です。
  4. 6工程が自動で走る — 送信停止 → 局番号を空に → 改名して再起動 → 名前解決 → 鍵登録 → 一覧に追加。
  5. 局番号を付ける — 登録直後は空です。子の画面（ブラウザ）から入れて完了。

3ハブを作る

親機を動かしたまま2台目を作れます。USB 1本で運びます。

先に読む — 現状このまま実行すると失敗します

素の Raspberry Pi OS（trixie）では bootstrap のフェーズ20 が必ず止まります。raspberrypi-kernel-headers が trixie に存在せず、docker-compose-plugin は Docker 社のリポジトリにしかないためです（親機は手で足してあります）。現場へ出す前にコード修正が要ります。詳細は5章。

取り扱い

出来たUSBには工場Wi-Fiのパスワードが入ります。鍵と同じ扱いにし、使い終わったら消してください。

手順

  1. 【数日前】固定IPを申請 — 新機の wlan0 のMACを許可登録してもらいます。MACは新機で cat /sys/class/net/wlan0/address。ウィザードは登録の有無を確かめません。
  2. 【親機】USBを作る — USBを挿して、デスクトップの ハブ用USBを作る をクリック。挿さっているUSBを自動で見つけ、確認してから書き出します。
  3. 【新機】コピー — USBを挿し、presence-hub-kit の「このUSBからコピー」をダブルクリック。開かないときは bash /media/pi/*/presence-hub-kit/copy-to-this-pi.sh。
  4. 【新機】ハブ初期設定 — デスクトップに出たアイコンをクリック。この時点では電波もコンテナも起動しません（親機とぶつからないため）。
  5. 【新機】再起動して子を迎える — 終わったら再起動し、2章の手順で子を足します。

4別の値にする項目

親機を動かしたまま2台目を作るとき、ここだけは必ず別にします。ウィザードは同じ値を弾きますが、理由を知っておくと迷いません。

項目衝突するとウィザードの扱い
ホスト名2台が互いの接続を切り合い、どちらのデータも届かない拒否。既定は <親>-2
工場の固定IP工場網全体が壊れる。自分たちだけの問題で済まない拒否。既定値なし
子Pi用AP名子がどちらのハブに繋ぐか不定になる拒否。既定は <ホスト名>-hub
STA_NO将来カメラを付けたとき記録の局番が重なる親の値+3 を自動。3台目以降は手で直す
同じでよいもの

工場のWi-Fi名・ゲートウェイ・DNS・Oracle の各項目は同じであるべきです。Enter で通してください。

例外

親と同じ名前・IP・AP名を使ってよいのは親機を止めて置き換えるときだけです。その場合は最初の質問で 2 を選びます。両方動かしたまま同じ値にすると必ず事故ります。

5既知の不具合

2026-09-23 にコードを行単位で突き合わせて見つかったもの。現場へ出す前に直すこと。

#重さ内容
B1止まるフェーズ20 が raspberrypi-kernel-headers を入れようとするが trixie に存在しない。aptは1つでも見つからないと何も入れずに失敗する。正しくは linux-headers-rpi-2712
B2止まるdocker-compose-plugin は Docker社のaptリポジトリにしかない。素のPiにはそのリポジトリが無い
B3効かないハブ初期設定の p（APパスワードだけやり直す）が実際のAPに反映されない。設定ファイルだけ新しくなる
B4危険フェーズ50 が戻り先Wi-Fi（F66）の自動接続を切るため、再起動後に新機へ遠隔で入れなくなる恐れ
B5誤表示2台目で「HIME-H-REAPに接続」が「APを起動できません」と誤警告する。AP自体は動いているので実害なし
B6読み残しsudo でpackするとドライバ源が見つからず、ドライバ無しのキットが「成功」で完成しうる。※「ハブ用USBを作る」アイコン経由なら対策済み
このハブで足りないもの

子ウィザードのSD書き込み経路は .kit/ap-join.env を必要としますが、このハブには .kit/ 自体がありません。不具合ではなく1号機だけの移行漏れです（2台目以降はウィザードが自動で書きます）。デスクトップのアイコンもまだ配置されていません。

根拠: scripts/setup-children-wizard.sh / scripts/setup-hub-wizard.sh / scripts/pack-hub-usb.sh / scripts/bootstrap/ の実装と、2026-09-23 のこのハブでの実機確認。
